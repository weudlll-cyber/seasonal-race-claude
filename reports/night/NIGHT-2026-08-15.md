# PIECE 1 — the hashed row may not use shorthand property syntax

**`scripts/check-fingerprint-payload.mjs`, merged `f2334ceb`.**

`fingerprint-default.mjs` hashes the rawData rows INCLUDING their key names, and those rows are built
at one place. While a property there was shorthand, a documentation pass renamed the local variable
and **shorthand renamed the emitted COLUMN with it**; `fairness-stats.mjs` read `sollRank`, got
`undefined`, every start row's band hit rate fell to 0.000, and the world fingerprint moved for a
race that was byte-identical. The only defence was a comment on one property.

**It PARSES.** A regex is a partial guard that looks exactly like a complete one — `{ a }` vs
`{ a: a }` vs `{ [k]: v }` vs `{ a() {} }` cannot be told apart by matching text across line breaks
and nested literals. It uses acorn through `scripts/lib/inertChange.mjs`'s own `acorn()`, so there is
one home for where the parser comes from.

**It anchors on the CALL SITE, not a name** — the defect it exists for WAS a rename, so anchoring on
a name would be anchoring on the thing that moves.

**Loud failures, all proven:** zero `rawData.push` call sites; a payload behind a variable; an
unparseable file; acorn unresolvable. A guard that cannot check is not a guard that passes.

**The fix that came with it:** nine of the ten named properties were shorthand. All ten are explicit
now. **The emitted object is identical and that was measured, not argued** — WORLD reproduces
`dc4647be0f55ebdb` and WORLD-OFF `854018ee5d3d83e1`, both `--check`ed against the record on the
committed tree.

**`acorn()` now tries the ROOT tree before the client tree.** It only ever looked in `client/`, where
eslint brings it — but CI's guard job does not install the client tree, so there it always resolved
to null. Harmless for `inertChange` (null means "not inert", which costs a fingerprint run) and fatal
for a guard that must parse.

**Named, not fixed — the spread exposure.** The same literal ends with `...r`. Measured from a row
the fingerprint run actually emitted: **a hashed row has 16 keys, 10 named at the call site and SIX
arriving through the spread** — `racerIndex`, `startRowIndex`, `indexInRow`, `finalT`, `finalRank`,
`finishTime`. They are named explicitly at `sim-fairness.mjs:3126-3131`, so the same door happens to
be shut there — **by accident, with nothing guarding it.** The guard PRINTS every spread on a passing
run rather than letting a reader assume the row is fully covered.

**Cost:** guard ~90 ms. CI's docs job gained its first dependency (acorn, root devDependency,
`npm ci --omit=optional --ignore-scripts`) at **~3 s**.

**Hygiene:** `check-fingerprint-payload.mjs` +266, its test +139, `sim-fairness.mjs` 6205 → 6210,
`inertChange.mjs` 189 → 202. Removed: nothing. Extracted: the acorn resolution stayed in
`inertChange.mjs` rather than being copied. **Noticed and left alone:** the spread exposure above.

**Proven both directions on the real tree, not only fixtures:** reverting `trackId` to shorthand
fails (exit 1, key named); restoring it passes (exit 0).

# PIECE 2 — the language rule and the closed quotation exception

**`scripts/check-language-closed.mjs`, merged `18e72696`.**

**The detection rule.** Two signals, either trips a line: an **umlaut** (a character English does not
use — mechanical, not a judgement), or **two or more distinct German function words on one line**.
Umlauts alone are not enough: "das ist nicht spannend" has none, and a rule that misses a whole
German sentence is worse than one that occasionally over-fires.

**Its false-positive behaviour was measured, and the first version HAD one.** Its own test asserted
that ordinary English passes, and caught this line failing:

```
// the racer's `soll` rank falls inside their assigned Bereich
```

Two German-looking words, one line, correct English. `soll` and `Bereich` are **column identifiers**
here (`sollRank`, `sollBereich`) that English prose legitimately names. Both are now excluded **by
name with the reason recorded** — the same move CONFIG-TRUTH-1 made for `duration` under R11. On the
shipped tree there is now **no line where the guard fires on correct English**.

**The allowlist is a FILE plus a COUNT.** A bare file-level allowance lets an allowed file quietly
gain German; a line anchor breaks whenever a line moves. Growing fails; shrinking fails too. **Every
count came from `--inventory` on the tree** — the hand-written first draft was wrong in fourteen of
twenty-five entries in both directions, caught immediately by the guard, which is the argument for a
count made against the guard's own author.

**Additions are hard, removals are easy.** The test carries a FROZEN set of paths and asserts
one-directionally: an allowlist entry not in it fails; a frozen path no longer allowed does not.

## What the tree actually contains — listed, not fixed

**27 files.** 11 are CLAUDE.md's grandfathered closing inventory. **14 are real pre-existing
violations of the permanent language rule**, each its own block:

| what                                                        | where                                                 |
| ----------------------------------------------------------- | ----------------------------------------------------- |
| an entirely German skill document (20 lines)                 | `.claude/skills/dev-start/SKILL.md`                   |
| **three German USER-FACING Dev Screen alerts**               | `BrandingProfiles.jsx`, `PlayerGroupsManager.jsx`, `TrackManager.jsx` |
| their German test names (7 lines each)                       | the three matching `.test.jsx`                        |
| German output strings in the sim report observer (6)         | `scripts/sim/observers/report.mjs`                    |
| German summary strings in a sweep driver (8)                 | `client/scripts/sweep-bufferPct-driver.mjs`           |
| German review markers in the server session code (3)         | `server/src/auth/session.js` + test                   |
| four one-line strays                                         | an e2e description, a backlog line, an archived tooltip |

**The three user-facing alerts are the worst of these and should go first** — they are the only
entries a player can actually see.

The remaining 2 are the detector itself: a German detector contains German (the umlaut class, the
word list, the fixtures). Allowed **by count** rather than excluded wholesale, so anything beyond the
machinery still fails.

## Two corrections to the premise

1. **`scripts/sim-fairness.mjs` contains NO German at all.** The spec named it alongside
   `report.mjs`, and a byte-oriented `grep '[äöü]'` agrees — it reports 45 lines. That is an
   artefact: **a bracket expression over UTF-8 matches the CONTINUATION BYTES of umlauts, which em
   dashes and typographic quotes share.** The same artefact reports 207 German lines in
   `docs/BACKLOG.md`, which has one. Decoded properly: 0.
2. **The closing inventory names `docs/fingerprints.json` as carrying two quotations. It now carries
   none** — the FINISH-PAIR-1 mint they sat in has since been superseded twice. The inventory is
   CLOSED and was not edited.

## The guard caught itself, and CI caught my false green

**A local green run meant nothing and this is the lesson worth keeping.** The guard reads
`git ls-files`, so its own brand-new files were **invisible to it until they were committed**. Every
local run before the commit scanned a tree that did not contain the guard. CI ran on the committed
tree, saw it, flagged the umlaut class and the German fixtures, and **failed correctly**. Read the
failure before judging it — this one was right.

**Hygiene:** guard +325, test +213. Removed: nothing. **`scripts/verify.test.mjs` 669 → 690, and

# PIECE 3 — what the silent hook let through (AUDIT, no repair)

**Read-only. Nothing was repaired, nothing restaged.**

## The mechanism, demonstrated rather than argued

`core.hooksPath` is **`.husky/_`** — a RELATIVE path. `git ls-files .husky` returns exactly one
entry, `.husky/pre-commit`; the `_` directory is husky's generated runtime and is untracked (its own
`.gitignore` contains `*`).

So in a linked worktree git resolves `core.hooksPath` against that worktree's root, finds no
`.husky/_/` there, and **runs no hook at all — silently, exit 0.**

Proven with a real worktree rather than reasoned about:

```
$ git worktree add --detach C:/ra-hookproof HEAD
$ ls C:/ra-hookproof/.husky/          → pre-commit
$ ls C:/ra-hookproof/.husky/_         → No such file or directory
$ git -C C:/ra-hookproof rev-parse --git-path hooks   → .husky/_
$ cd C:/ra-hookproof && git commit …  → committed, exit 0, NO hook output whatsoever
```

Every commit made in the main tree tonight printed `GUARDS: PASS 7 FAIL 0`. That commit printed
nothing. **The bypass is total and it is silent.**

**There are 45 stale worktree stubs in `.git/worktrees`, dated 2026-06-05 through 2026-08-14** — so
worktrees were in use across the whole recent history, not in a narrow window. Their reflogs are
empty, so worktree metadata cannot identify which commits came from them.

## What the hook actually checks, run against master's current tree

| check                                          | result on master today |
| ---------------------------------------------- | ---------------------- |
| `check-fingerprints`                           | **PASS** |
| `check-measured-stamps`                        | **PASS** |
| `check-config-claims`                          | **PASS** |
| `check-doc-facts`                              | **PASS** |
| `check-writable`                               | **PASS** |
| `check-config-keys`                            | **PASS** |
| `check-fallback-agreement`                     | **PASS** |
| `prettier --check src` (lint-staged's first half) | **PASS** — "All matched files use Prettier code style!" |
| `eslint src` (lint-staged's second half)       | **PASS** — 0 errors, 4 `no-unused-vars` warnings |

**A clean result is a real result: nothing that slipped through still matters.**

## Bounding the past

The hook's first action is `prettier --write` over staged `client/src` files, so **a commit whose own
`client/src` blobs are prettier-dirty at that commit did not run it.** That is the only mechanical
trace a missing hook leaves in history.

**549 commits checked** (every commit touching `client/src` since the first worktree stub;
16 more skipped as touching no lint-staged extension). Each commit's own added/modified blobs were
extracted with `git cat-file` and checked against the repo's real `.prettierrc`.

All three fall in the peak worktree period — 14 stubs were created on 2026-08-07, 5 on 08-08, 7 on
08-10.

**What they left behind that today's checks would still reject: NOTHING.**

**The detector was calibrated before it was trusted.** Its first version reported 11 of 12 commits
dirty — including commits made tonight in the main tree, which certainly ran the hook. The cause:
prettier resolves its config relative to the FILE, so blobs extracted to a temp directory were
checked against prettier's DEFAULTS rather than this repo's `.prettierrc`. Passing `--config`
explicitly took it to 0 of 12 on known-hooked commits, which is what makes the 3 of 549 meaningful.

## What this audit CANNOT say

- **It cannot see a commit that skipped the hook and happened to be prettier-clean anyway.** Most
  edits are. The true number of unhooked commits is ≥ 3 and unknowable from history.
- **It says nothing about the seven guards at the time of those commits** — they check the whole
  tree, and later commits moved it. Only the current-tree result above speaks to them, and it is
  clean.
- **`.git/worktrees` grew by one during this audit.** `git worktree remove` deleted the checkout but
  could not delete the stub: `failed to delete '.git/worktrees/ra-hookproof': Permission denied` —
  the reparse-point condition already in the backlog, which `git worktree prune` also cannot clear.
  45 became 46. The proof commit is unreachable from master.

## PROPOSAL — make the bypass loud instead of silent

The repair is not to fix the past; the past is clean. It is to stop the mechanism.

**Track the hook shim.** `core.hooksPath` points at an untracked directory, which is why a fresh
worktree silently has no hooks. Pointing it at a TRACKED directory containing a one-line shim that
execs husky's runtime would give every worktree the hook — and, when husky is not installed, a shim
that says so out loud instead of a checkout that quietly enforces nothing.

**Failing that, a `post-checkout` marker** that refuses to be silent: a worktree with no resolvable
hooks prints one line saying so. Cheap, and it converts an invisible condition into a visible one.

# PIECE 4 — the declared engine reach becomes a contract

**`REACH-CONTRACT-1`, merged `6ede7386`.**

## The silent failure, precisely

`closureOf` returns `[]` for a path that does not exist. So a guard declaring
`reach: ["client/src/modules/raceCore.js"]` for a file that has since been renamed contributes
**nothing** to its own dependency set. It still declares itself. It still prints its
`reach=N entry point(s)` line. And it quietly stops selecting on everything that file imports —
after which `npm run verify` **skips it for a diff it should have run on**, with a skip reason that
reads perfectly honest.

**That is the worst shape a guard can take, because it looks exactly like coverage.**

`files:` and `dirs:` have the same hole from the other direction: a declared path that does not
exist can never match, so the guard narrows without saying so.

## Where the check lives, and why there

**In the RESOLVER (`scripts/lib/routing.mjs`), not in a `check-*.mjs` guard.**

A guard checking the router would itself be **routed by the router** — the one path that most needs
the check is the one that could skip it. In the resolver, every consumer of a declaration (verify,
`engine-reach`, the tests) gets it and none can opt out.

`collect()` now returns `invalid` alongside `undeclared` — **collected rather than thrown**, so a
caller decides what a broken declaration means. `verify` REFUSES on it with **exit 2**, the same code
an empty run uses (R0a), and it is not a guard failure.

**It refuses BEFORE the plan is computed**, because the plan is the thing that cannot be trusted: a
route computed from a broken declaration is not a route, and printing it would give the run the
appearance of having decided something.

## The tree passes as it stands

**All 46 declared paths across every guard exist and are of the right kind.** Making the declaration
binding cost nothing and forced neither side to move — the good outcome, and the one the brief said
to report either way.

## Proven in both directions against the LIVE router

```
$ # add reach: ["client/src/modules/raceCoreRENAMED.js"] to check-doc-facts
$ npm run verify -- --dry
  REFUSED: 1 declared path(s) do not resolve, so the routing cannot be trusted.
           check-doc-facts  reach: client/src/modules/raceCoreRENAMED.js
             does not exist — its closure resolves to NOTHING, so this guard silently stops
             selecting on everything that file reaches
                                                                              → exit 2
$ # restore
$ npm run verify -- --dry                                                     → exit 0
```

Three tests carry it, each stating what breaks if deleted: the tree's own baseline (without it, a
declaration could rot and only synthetic cases would still pass), a missing `reach` entry, and a
declared path of the **wrong kind**.

**Wrong-kind checking was not in the brief**, and it is in because the probe that established the
baseline tripped over it: the first version classified `notDirs` as naming files and reported
`client/e2e/` as a violation. **The guard was wrong, not the declaration** — and the fix generalises
to a real hole, since `files: ["docs/"]` would otherwise pass while matching nothing.

**Hygiene:** `routing.mjs` 255 → 319, `verify.mjs` 589 → 617, `verify.test.mjs` 690 → 742. Removed:
nothing. Extracted: `declaredPathProblems()`, exported so the tests assert on the same function
verify refuses on rather than a copy of its logic. **Noticed and left alone:** `resolveGuard` still
absorbs a missing path into an empty closure — the refusal happens in `collect()`, one level up, so
a caller that resolves a single guard directly bypasses it. No such caller exists today.

# PROPOSALS

1. **Track the hook shim, and end the silent bypass** (Piece 3's proposal, restated because it is
   the biggest one here). `core.hooksPath` points at an untracked directory, so every worktree
   silently enforces nothing. A tracked shim directory that execs husky's runtime — and says so out
   loud when husky is absent — converts an invisible condition into a visible one. Tonight's audit
   says the past is clean; it says nothing about the next worktree.

2. **Close the `...r` spread in the hashed row** (Piece 1's named-not-fixed finding). **Six of the
   sixteen hashed columns arrive through a spread** the new guard is blind to. They are named
   explicitly in `runSingleRace`'s return literal — by accident, with nothing holding them there. The
   same parser that guards the push site can guard that literal; it is the same defect through a
   different door and it is a small block.

3. **Delete the three German user-facing alerts first.** Of the 14 pre-existing language violations,
   three are strings a *player* can see (`BrandingProfiles`, `PlayerGroupsManager`, `TrackManager`).
   Each is one line plus its German test names. Removing them shrinks the frozen allowlist by six
   entries, which is the direction that list is built to move in — and the guard now makes the
   shrinkage mandatory rather than optional, since a stale allowance fails.

4. **Give `check-language-closed` a second signal for German that has neither an umlaut nor two
   listed words.** Its declared blind spot is a lone German word — `Weltall-Strecke` in a test name
   passes today. A character-trigram model over the line would catch it without a word list, and
   would not need tuning per domain noun. Worth doing only if a real miss turns up; recorded so the
   hole is not rediscovered.

5. **Re-run the hook audit's detector as a guard, not a one-off.** The 549-commit prettier sweep took
   ~10 minutes and answered a question nobody could answer before. As a guard over the last N commits
   it would be cheap, and it would catch the next unhooked commit on the day it lands rather than in
   the next audit.
