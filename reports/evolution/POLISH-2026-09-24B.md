★ **No fix was attempted, deliberately.** A flake whose rate nobody has measured cannot be fixed on
purpose, and "I changed something and it stopped failing" is not evidence when the failure rate is
unknown.

★★ **What 0 failures in N runs does and does not establish.** It bounds the rate: at N=20 a
one-in-five flake would almost certainly have shown (the chance of missing it is 0.8²⁰ ≈ 1.2%), and a
one-in-fifty would very likely not have (0.98²⁰ ≈ 67% chance of missing it). **So this refutes a
frequent flake and says nothing about a rare one.** The honest verdict is *not reproducible at this
rate*, not *fixed*.

★ **A caveat about the conditions, stated because it could matter.** These runs shared the machine
with the night's own editing and test work. Load changes timing, and timing is what a mock-scope race
depends on — so if anything the conditions were *more* hostile than a quiet machine, not less. The
suite also grew during the night (266 → 267 files) as this night's own tests landed.

## 2 · WHAT THE BACKGROUNDS COST AT FIRST PAINT — **nothing, and the question had the wrong shape**

★★★ **There are ZERO image bytes in the client bundle.** The production build is **3.49 MB** across
52 files — 0.89 MB JavaScript, 0.06 MB CSS, 0.9 KB HTML, 2.54 MB other (fonts and sprites) — and not
one background among them. Backgrounds are fetched at runtime by URL
(`trackLoader.js:53` builds `/api/tracks/<id>/background`) and cached per session
(`bgImageCache.js`).

**So "51.6 MB at first paint" is a false premise: first paint costs 0 background bytes.** What the
51.6 MB actually is, is a per-track cost paid when a track is chosen:

| track | MB |
|---|---|
| river-run | **9.69** |
| seatrack | 9.53 |
| mountainstreet | 9.32 |
| luger-hill | 4.81 |
| garden-path | 3.68 |
| searound | 3.61 |
| dirt-oval | 3.16 |
| ice-track | 3.07 |
| city-circuit | 2.66 |
| space-sprint | 2.04 |
| **total / median / worst** | **51.57 / 3.61 / 9.69** |

★ **What that implies, without proposing anything.** One track, once per session — not 51.6 MB, and
never all ten. But the worst single track is **nearly three times the entire application bundle**, and
on a 10 Mbit link that is about **8 seconds** before the track is drawable. The three heaviest
(river-run, seatrack, mountainstreet) are 28.5 MB between them and are the only ones above 5 MB.
★ **No optimisation was attempted** — changing image handling is a visible change and is his.

| | item | what shipped | tests |

| 3(a) | **Q-22** | A crash can no longer lose a hand-drawn track. **Offers** the draft rather than restoring silently, and never offers over work already on screen. | 9 |

★★ **3(a) closed as a HALF, and the remainder was split out rather than implied.** Q-22 specified a
**per-track** key so that editing an existing track is drafted too. What shipped is a single key,
written and offered only outside load mode. The write is gated the same way the offer is — writing
drafts that are never shown stores data nobody sees, which is worse than not storing it. **The
load-mode half is now Q-22b in PART ONE**, with why the two are not the same severity: the new-track
case loses *all* the work, the load-mode case loses an edit to work already safe on the server.

★★ **3(d) was a TEST GAP, NOT A DEFECT, and is reported as such.** `PUT` spreads the client body and
then writes `isDefault: existing.isDefault` after it (`tracks.js:542`), so the protection was already
there — only untested. **Honesty proof, run rather than claimed:** deleting that line turns both new
tests red; restoring it turns them green.

★ **3(b)'s two deliberate limits.** The signal handler does the **file half only** — on a signal the
process is going away and an awaited HTTP round-trip may never resolve — and it **re-raises the
signal** rather than swallowing it. A harness that makes Ctrl+C stop working is worse than one that
leaves files behind.

★ **3(c) runs before `createApp()`**, so it cannot race a live write and delete a tmp that was about
to be renamed — which would turn a crash-safety measure into a cause of data loss.
