## 2. ★ TWO OF THE SEVEN ARE THE SAME SHAPE ONE LAYER DOWN

This is the finding, and it is not the one the list suggests.

**`VERIFY-RULES.md` R10's prune paragraph was corrected on 2026-09-02.** It had said for four months
that prune *"cannot delete the stale stubs here"*; WORKTREE-STUBS-1 proved the three-line recipe and
the paragraph was fixed. **`BACKLOG.md`'s open entry, which copied that claim and built an
instruction on top of it — "do not add prune to the ship ceremony" — was not.**

**`BACKLOG.md:627`'s `corridor-truth` line was corrected on 2026-09-02**, and R16 with it.
**`raceDriver.mjs:122`, a code comment that copied the same sentence, was not.**

**So two of the seven are not stale claims that nobody revisited. They are corrections that landed at
the source while the copy kept speaking** — and in one case the copy was load-bearing, because it was
phrased as an instruction rather than as a fact. **A correction that fixes the source and not the
copies has done half the work and looks like all of it.**

## 3. ★ THE COUNT WAS REMOVED RATHER THAN UPDATED

`VERIFY-RULES.md` said **103/103**; the honest update is **106**, of which 105 can pass. **Writing
106 would have reset the clock on exactly the failure being fixed.** The numerator stopped moving
while the denominator did not, because a suite's size changes when anybody adds a spec and a sentence
in a rules document does not notice.

**`NIGHT-RUN.md` is the one home** and it already says *"no count is written here as a target: run it
and read what it says."* `VERIFY-RULES.md` now points there and states no count. **The same reasoning
BACKLOG's worktree entry applied to itself** — *"THE COUNT IS DELIBERATELY NOT WRITTEN HERE ANY MORE,
it has been wrong three times"* — and that entry was right.

The `TAGS.md` pair is the same move: **a register of PAST states is the last place that should name
the present one.**

## 4. CLOSED ON THE WAY, BY ITS OWN VERIFY COMMAND

`BACKLOG.md`'s `.git/worktrees` entry carried **`verify:` `ls .git/worktrees | wc -l` — still open
while it returns more than 0.** It returns **0**. Closed, mechanically, on the entry's own stated
condition.

**Its live remainder is re-filed as its own open line rather than kept open under a closed one.**
Nothing removes a throwaway worktree in a `finally`, so SHIP-CEREMONY step 13 is a **cure, not a
prevention**, and the stub is still created every time. That is a different question from the one the
closed box asked, and burying it inside a struck entry is how live work disappears.

**Open boxes 57 → 57.** One closed, one filed. Saying that plainly is better than reporting a
decrease that did not happen.

## Limits

**This is an instance sweep, not a class removal**, and WHATS-LEFT-1 ranked it third for that reason.
Nothing built here stops the next correction from fixing a source and leaving its copies. **The one
mechanism that would — a guard that knows a sentence copies another — is PATTERN-CATCHABILITY-1's S3,
and it needs the copy to opt in by citing what it copies.** Piece 7's citation convention is the
nearest thing to a foundation for it and does not build it.

**The `TAGS.md` fix names no current hash, so it cannot go stale, but it also cannot help a reader who
wanted one.** That is the trade the one-home rule makes everywhere and it is not free.

**Seven sites were closed; the corpus was WHATS-LEFT-1's list, re-confirmed at the tree.** No fresh
survey for second sites of OTHER corrections was run, so this says nothing about how many more exist.
SECOND-SITES-2's honest combined figure — **15 of 32 = 47%** — is unaffected by this piece, because
fixing sites does not change the rate at which they were created.
