## 1. What branding is

Branding is an optional feature that lets a game-master dress a session of races in house colors — a
named event, a logo, and two accent colors that tint visible UI elements. It is deliberately not the
main feature of RaceArena; it sits in the background. The intended use case is a recurring tournament
or sponsored event where the operator wants consistent visual identity across screens. Phase 3
(trackside banners, racer livery) has been **cut** by owner decision and will not be built.

## 2. Current built state (Phase 1 complete, owner-confirmed 2026-06-12)

### Branding profiles

Profiles are created, edited, and deleted in **DevScreen → Branding** (`BrandingProfiles.jsx`). The
form is full CRUD. Every saved profile has the following fields
([`BrandingProfiles.jsx:17–29`](../client/src/screens/DevScreen/sections/BrandingProfiles.jsx#L17-L29)):

| Field | Type | Notes |
|---|---|---|
| `name` | string | Required. Display name for the profile (e.g. "Spring Cup"). |
| `eventName` | string | Required. The event title shown in the SetupScreen header, on the race canvas, and in the ResultScreen brand block. |
| `subtitle` | string | Optional secondary line (e.g. season or sponsor name). Shown below `eventName` in the SetupScreen header, on the race canvas, and in the ResultScreen brand block. |
| `primaryColor` | string | Hex color. Drives `--brand-primary` CSS var. `eventName` is rendered in this color everywhere it appears. Default `#e63946`. |
| `secondaryColor` | string | Hex color. Drives `--brand-secondary` CSS var. `subtitle` is rendered in this color everywhere it appears. Default `#f4a261`. |
| `sponsorText` | string | Sponsor credit text. Displayed as a grey footer strip on the ResultScreen ([`ResultScreen/index.jsx:199`](../client/src/screens/ResultScreen/index.jsx#L199)). |
| `logo` | string | Base64 data URL of an image. Shown as corner logo overlay during races (bottom-right) and as a top-left absolute overlay on the ResultScreen. |
| `isDefault` | boolean | UI star indicator only — **does NOT drive activation** (see below). |
| `logoMaxHeight` | number (px) | Max height of the in-race corner logo. Range 40–160. Default `90`. Not used on ResultScreen (which uses a fixed 210px max). |
| `logoOpacity` | number (0–1) | Opacity of the logo in both in-race overlay and ResultScreen. Default `0.9`. |
| `logoCorner` | string | In-race logo position. Supported values: `'bottom-right'` (default), `'top-right'`. The renderer selects from a lookup map with `'bottom-right'` as fallback ([`BrandLogoOverlay.jsx:16–18, 30`](../client/src/screens/RaceScreen/BrandLogoOverlay.jsx#L16-L30)). Position is **data-driven, not hardcoded**. What is missing is a UI control in BrandingProfiles to set it; see §4. |

Each saved profile gets an `id` generated by `newId()` (`storage.js:158`) prepended on save.

### Storage

Both the profile list and the active-session pointer live in **`window.localStorage`** — not on the
server.

| Key | Constant | Default | Content |
|---|---|---|---|
| `racearena:branding` | `KEYS.BRANDING` ([`storage.js:13`](../client/src/modules/storage/storage.js#L13)) | `[]` | Array of profile objects |
| `racearena:activeSession` | `KEYS.ACTIVE_SESSION` ([`storage.js:14`](../client/src/modules/storage/storage.js#L14)) | `{ activeBrandingProfileId: null }` | Active profile id or null |

**Implications:**
- Per-browser, per-device. A profile created on one machine is not visible on another.
- The browser's localStorage quota is typically ~5 MB. Base64 logos are large (a 200 KB PNG becomes
  ~270 KB as a data URL). A few logos can consume the quota; the app logs a warning and silently
  skips the write if the quota is exceeded (`storage.js:45–47`). Operators with large logos should
  compress before uploading.
- No server backup. Clearing browser data deletes all profiles.

### Activation (SetupScreen selector)

SetupScreen reads both `KEYS.BRANDING` and `KEYS.ACTIVE_SESSION` via `useStorage`. A `<select>`
dropdown appears in the header **only when at least one profile exists**
([`SetupScreen.jsx:501–524`](../client/src/screens/SetupScreen/SetupScreen.jsx#L501-L524)):

```
Branding: None ▼
           Spring Cup
           Winter League
```

Selecting a profile writes `{ activeBrandingProfileId: "<id>" }` to `KEYS.ACTIVE_SESSION`.
Selecting "None" writes `{ activeBrandingProfileId: null }`.

**Important:** the `isDefault` flag on a profile is a cosmetic star in BrandingProfiles — it is set
by "Set as default" but is **not read anywhere** to drive automatic activation. The game-master must
explicitly select a profile in the SetupScreen selector to activate it.

### CSS-variable injection

Whenever the active profile changes, a `useEffect` in SetupScreen writes two CSS custom properties
directly onto `document.documentElement.style`
([`SetupScreen.jsx:163–178`](../client/src/screens/SetupScreen/SetupScreen.jsx#L163-L178)):

```js
root.setProperty('--brand-primary', profile.primaryColor);
root.setProperty('--brand-secondary', profile.secondaryColor);
```

When the selector is set to "None", both properties are **removed** (not set to a default):

```js
root.removeProperty('--brand-primary');
root.removeProperty('--brand-secondary');
```

Because these are inline styles on `<html>`, they persist across React navigation (SPA routing does
not reload the page). They are cleared only on full browser reload, at which point SetupScreen
re-mounts and re-injects from the stored active session.

The `:root` block in `main.css` does **not** define `--brand-primary` or `--brand-secondary` as
static values ([`main.css:18–19`](../client/src/styles/main.css#L18-L19)). Each CSS use-site
provides its own fallback via `var(--brand-X, <fallback>)` so that an unset variable never changes
the look of unbranded sessions.

### 2a. Visual results — Steps 1–2 (built earlier)

**Screen-transition fade color** — [`TransitionOverlay.css:13`](../client/src/contexts/TransitionOverlay.css#L13):

```css
background: var(--brand-primary, #000);
```

With a profile active: the full-screen fade between screens flashes in the brand's primary color.
With no profile: the fade is black, identical to before branding was added.

**In-race corner logo overlay** — [`BrandLogoOverlay.jsx`](../client/src/screens/RaceScreen/BrandLogoOverlay.jsx),
rendered as a sibling DOM element inside `.race-canvas-wrapper` in `RaceScreen/index.jsx`:

- Reads the active profile's `logo`, `logoMaxHeight`, and `logoOpacity` fields.
- Positions itself **bottom-right** (`bottom: 16px; right: 16px`) via `CORNER_STYLES` inline style.
- `pointer-events: none`; `drop-shadow` filter for legibility on any background.
- Renders `null` when there is no active profile or the profile has no logo set.

```jsx
<div className="brand-logo-overlay" style={corner}>
  <img ... style={{ opacity: profile.logoOpacity ?? 0.9, maxHeight: (profile.logoMaxHeight ?? 90) + 'px' }} />
</div>
```

### 2b. Visual results — Phase 1 completion (built in final steps)

#### Event name and subtitle — one profile source, two reading paths

The active branding **profile** is the single source of truth for `eventName` and `subtitle`. How
each surface reads them differs — there is no single shared chain:

- **Race canvas**: receives them via a carrier chain (raceSettings → `sessionStorage.activeRace` →
  `raceData` → `drawTitle`/`drawTitleOpen`).
- **ResultScreen brand block** (eventName, subtitle, logo, colors): resolved directly from
  `localStorage` via `useStorage`, independent of the race object — the same pattern as
  `BrandLogoOverlay`
  ([`ResultScreen/index.jsx:26–30`](../client/src/screens/ResultScreen/index.jsx#L26-L30)).

`sponsorText` is the one exception: the ResultScreen reads it from `race.sponsorText` (carrier path
[`SetupScreen.jsx:386`](../client/src/screens/SetupScreen/SetupScreen.jsx#L386), see "Sponsor strip
carrier" below), not directly from the profile.

The canvas carrier chain in full:

1. **Seed into raceSettings**: when the active profile changes, a `useEffect` sets
   `raceSettings.eventName` from `profile.eventName`
   ([`SetupScreen.jsx:181–185`](../client/src/screens/SetupScreen/SetupScreen.jsx#L181-L185)).

2. **SetupScreen header**: rendered in the header beside the RaceArena wordmark when non-empty
   ([`SetupScreen.jsx:457–499`](../client/src/screens/SetupScreen/SetupScreen.jsx#L457-L499)).
   `eventName` is styled in `var(--brand-primary)` and `subtitle` immediately below it in
   `var(--brand-secondary)`.

3. **Carried into activeRace**: written to `sessionStorage.activeRace` when a race is started
   ([`SetupScreen.jsx:384–385`](../client/src/screens/SetupScreen/SetupScreen.jsx#L384-L385)):
   ```js
   eventName: raceSettings.eventName,
   subtitle: activeBrandProfile?.subtitle ?? '',
   ```

4. **Race canvas title overlay**: `RaceScreen` loads `raceData` from `sessionStorage.activeRace`
   ([`RaceScreen/index.jsx:332–334`](../client/src/screens/RaceScreen/index.jsx#L332-L334))
   and passes it to:
   - `drawTitle(ctx, shape, raceData)` for closed tracks
     ([`RaceScreen/index.jsx:1449`](../client/src/screens/RaceScreen/index.jsx#L1449),
      [`overlayRendering.js:22–41`](../client/src/screens/RaceScreen/drawing/overlayRendering.js#L22-L41))
   - `drawTitleOpen(ctx, raceData)` for open tracks
     ([`RaceScreen/index.jsx:1447`](../client/src/screens/RaceScreen/index.jsx#L1447),
      [`overlayRendering.js:48–62`](../client/src/screens/RaceScreen/drawing/overlayRendering.js#L48-L62))

   Both functions render `eventName` in gold (`#ffd700`) and, when present, `subtitle` below it in
   a dimmer gold (`rgba(255,215,0,0.65)`).

5. **ResultScreen brand block** (direct storage read, not via carrier): `ResultScreen` calls
   `useStorage(KEYS.BRANDING)` and `useStorage(KEYS.ACTIVE_SESSION)` directly
   ([`ResultScreen/index.jsx:26–30`](../client/src/screens/ResultScreen/index.jsx#L26-L30))
   and renders ([`ResultScreen/index.jsx:87–111`](../client/src/screens/ResultScreen/index.jsx#L87-L111)):
   - `eventName` in the profile's own `primaryColor`
   - `subtitle` (if present) in `secondaryColor`
   - track name and elapsed time below

#### ResultScreen full redesign

The ResultScreen is no longer a bare `<h1>`. As of `b9a2f03`:

- **Brand identity block** (conditional on active profile): event name in `primaryColor`, subtitle in
  `secondaryColor`, track name · elapsed time
  ([`ResultScreen/index.jsx:87–111`](../client/src/screens/ResultScreen/index.jsx#L87-L111)).
- **Logo top-left**: when the active profile has a logo, it is rendered as a `position: absolute`
  overlay in the top-left corner of the results card, outside the vertical flow
  ([`ResultScreen/index.jsx:113–123`](../client/src/screens/ResultScreen/index.jsx#L113-L123),
   [`ResultScreen.css:76–89`](../client/src/screens/ResultScreen/ResultScreen.css#L76-L89)).
  Uses `logoOpacity` from the profile; fixed max of 210 px (not `logoMaxHeight`).
- **Podium** (ranks 1–3): animated slots with racer icon, name, and finish time
  ([`ResultScreen/index.jsx:125–170`](../client/src/screens/ResultScreen/index.jsx#L125-L170)).
- **Scrollable rank panel** (ranks 4+): fixed-height panel showing 5 rows before scrolling
  ([`ResultScreen/index.jsx:172–189`](../client/src/screens/ResultScreen/index.jsx#L172-L189)).
  `max-height` is set to the measured actual row height × 5 (233 px).
- **Sponsor strip**: a grey footer line rendered when `race.sponsorText` is non-empty
  ([`ResultScreen/index.jsx:199`](../client/src/screens/ResultScreen/index.jsx#L199)).

#### Per-racer finish times

Every racer's physics-clock timestamp is recorded the moment they cross the finish line:

```js
r.finishTimeMs = physicsTs;  // RaceScreen/index.jsx:1019
```

It is carried into the `finishOrder` array written to `sessionStorage.raceResults`:

```js
finishTimeMs: r.finishTimeMs ?? null,  // RaceScreen/index.jsx:1059
```

Formatting is handled by a shared utility
([`client/src/utils/formatRaceTime.js`](../client/src/utils/formatRaceTime.js))
that formats milliseconds as `ss.hh` (e.g. `29.34`) or `m:ss.hh` (e.g. `1:05.32`). It is consumed
by both the in-race live scoreboard
([`RaceScreen/index.jsx:1639–1640`](../client/src/screens/RaceScreen/index.jsx#L1639-L1640))
and the ResultScreen podium slots and rank rows.

#### Sponsor strip carrier

`sponsorText` is copied from the active profile into the race object when a race starts:

```js
sponsorText: activeBrandProfile?.sponsorText ?? '',  // SetupScreen.jsx:386
```

It travels in `sessionStorage.activeRace` → `sessionStorage.raceResults` → ResultScreen, where it
is rendered as a centered grey footer below the Back button
([`ResultScreen/index.jsx:199`](../client/src/screens/ResultScreen/index.jsx#L199)):

```jsx
{race?.sponsorText && <div className="result-sponsor">{race.sponsorText}</div>}
```

## 5. Deliberately out of scope / deferred decisions

### Phase 2 — further canvas overlays (deferred, not cut)

Any branding beyond the current `drawTitle`/`drawTitleOpen` call (e.g. countdown overlay in brand
colors, mid-race lower-third) touches the requestAnimationFrame render loop and CameraDirector
pipeline. Deferred until a future phase.

### Phase 3 — trackside banners and racer livery (CUT)

Per owner decision, trackside banners and racer livery are not in scope. These would require canvas
rendering changes and new asset pipelines. They will not be built.

### Open product decision — localStorage vs server-side brand store

Branding data currently lives in `localStorage` (per-device, no sharing, ~5 MB quota). If branding
ever needs to be shared across machines (e.g. multiple operator tablets at an event) or if the logo
quota becomes a practical problem, the profiles would need to move to the server
(`POST /api/branding-profiles` or similar). This is not urgent for the current single-device use
case and has not been decided. Logged here so it is not forgotten.
