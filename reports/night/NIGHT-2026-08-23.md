## The machine, and how it was split

Read before launching, as the addendum requires:

| | |
| --- | --- |
| logical cores | **14** |
| already resident | API on **4000** (1 proc), preview on **4173** (2 procs), **10** node processes, **37** browser processes |
| given to the sweep | **8 workers** |
| kept free | **6 cores** — at least two for the paper pieces' reading, grepping and doc guards, the rest as headroom for the resident processes |

**Why 8 and not more.** The machine is not idle: a preview server, an API and 37 browser processes
are resident, and an earlier run today measured a single sim race slowing from 94 s solo to 155–190 s
under only five-way contention. Giving the sweep 10+ workers would take everything and leave the
paper pieces starved, which the addendum names as over-parallelised. **8 of 14 is the large share
while leaving the reserve.**

**How the parts are kept from spoiling each other.** The sweep runs in **its own git worktree**
(`c:/tmp/night-sweep`, branch `night/sweep-tree`), so the main tree is never switched under a running
measurement. The paper pieces own the main tree and merge there one at a time. **Before every merge
its diff is checked to touch only `docs/` and `reports/`** — never a file the sweep reads.
