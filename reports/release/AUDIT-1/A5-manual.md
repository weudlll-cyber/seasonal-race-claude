Tree reviewed: `C:/tmp/a1` (origin/master `e164bb68`); VPS install scripts from `C:/tmp/a1v` (branch
`feat/vps-install`). Read-only review. No server was started and no network request was sent. Two

two regular expressions (A5M-02, A5M-03). Paths below are relative to `C:/tmp/a1` unless they start
with `a1v:`.

Severity is kept conservative. "To verify" marks a claim that is read from code but has not been run

## 3. Checked and found OK

**Sign-in, sessions, cookies**
- Cookie flags: `httpOnly: true, sameSite: 'lax', secure: cookieSecure, path: '/'` (`session.js:102-108`). The cookie is `secure` by default in production (`cookiePolicy.js:42-48`), and it uses the `__Host-` name when Secure is guaranteed (`session.js:34-49`). `saveUninitialized: false`, `resave: false` (`:100-101`).
- Production refuses to start without `RA_SESSION_SECRET` (`session.js:68-73`). The installer generates it with `openssl rand -hex 32` (64 hex characters, `a1v:install.sh:78-80`, `:292`).
- The session is regenerated on login (`authRouter.js:218`) and on setup (`:146`), and destroyed on logout with the cookie cleared (`:235-245`).
- Invalidation: `sessionEpoch` is bumped inside the same serialised write as the new hash (`usersStore.js:321-325`) and compared on every request (`guards.js:158-160`). A deleted user fails closed (`guards.js:149-153`). Role and team are read from the record on every request, never frozen into the session (`guards.js:186-192`).
- Password hashing: bcrypt, cost 12 (`usersStore.js:9`, `:19`, `:36`). `verifyPassword` turns a bcrypt error into `false` (`:39-45`).
- Enumeration: an unknown user spends a real cost-12 dummy hash (`authRouter.js:22`, `:207-209`), and the 401 text is the same for both cases (`:209`, `:214`). Change-password returns the same 401 text (`:283`). The user list is admin-only (`guards.js:24-29`).
- First admin: a header-only token (`authRouter.js:57`), compared in constant time (`:28-32`). Unset and wrong tokens get the same 403 (`:59-76`), and no token value is logged (`:71-74`). An O_EXCL marker gives exactly one winner (`:87`), with a post-gate user count (`:98-108`). Role and team are never taken from the body (`:124-131`). Setup is rate-limited (`app.js:64`).
- Token removal after the first admin: `sed -i '/^RA_BOOTSTRAP_TOKEN=/d'` followed by recreating the app (`a1v:racearena:328-333`). The installer stops (set -e) before this step if setup failed.
- Admin recovery is host-only CLI with no HTTP (`recoverAdmin.js:1-12`). The password never comes from argv: the CLI uses an env var or a no-echo TTY prompt (`scripts/recover-admin.mjs:68-148`). The audit log never contains the password (`recoverAdmin.js:23-27`).
- `users.json` is written 0600, and the server refuses to continue if it is left more permissive (`usersStore.js:171-189`).

**CSRF / CORS**
- Mutating `/api` requests need an Origin (or Referer) that is the server's own origin or an allow-listed one. `null` is refused (`csrf.js:106-108`). Strict mode is the default in production (`:62-67`, `:99-101`). Combined with SameSite=Lax this is sound, apart from A5M-01 (case) and A5M-02 (regex).
- CORS: an explicit list or `false`, never a wildcard with credentials (`csrf.js:52-55`).

**Uploads**
- Magic bytes are authoritative for PNG, JPEG and WebP (`imageUpload.js:27-56`). SVG and anything else are refused. The filename is built server-side as `<record id>.<ext>`, and the extension comes from the *detected* type (`tracks.js:615-616`, `brands.js:311-312`, `racers.js:278-279`). Record ids are either server-generated (tracks: 12 hex characters, `tracks.js:244-246`) or `isValidId` `^[a-z0-9_-]+$` (`isValidId.js:16-18`). No traversal is possible through an id.
- Serving: the Content-Type comes from an extension whitelist, else `application/octet-stream`, with `X-Content-Type-Options: nosniff` (`tracks.js:483-485`, `brands.js:287-289`, `racers.js:254-256`), and helmet adds nosniff globally. An image MIME type plus nosniff makes a polyglot inert. No `Content-Disposition` is needed for image types.
- **No image is decoded server-side** (no sharp, jimp or canvas in `server/package.json`), so there is no decompression-bomb surface on the server.
- Request-parameter → path: every `join(…, req.params…)` happens only after a Map lookup has found the record (`brands.js:219`, `:249`; `playerGroups.js:157`, `:172`; `racers.js:190`, `:220`). The surface-classes PUT validates the path id first (`surfaceClasses.js:140-141`, `:157`). Tracks use `track.id` (`tracks.js:556`). Stores are `Map`s, so `__proto__` as an id is harmless.

**SQL**
- `raceStore.js`: every value is a `?` parameter (`:223`, `:236`, `:404`, `:421-429`, `:459-462`, `:503`, `:521-523`, `:539-541`, `:555-558`, `:585-589`, `:619`). Interpolated identifiers are module constants: table names in `putContent` come only from the literals `'rosters'` and `'racer_types'` (`:324`, `:330`), column names from a server-built object (`:420`), and the trigger table list is a literal (`:187`).
- Migrations interpolate only constants and schema metadata (`migrateClientIdPerTeam.js:48-117`, `migrateRaceSource.js:55-87`). The session store library uses prepared statements (`better-sqlite3-session-store/src/index.js:54-214`).

**Client XSS sinks**
- No `dangerouslySetInnerHTML`, `innerHTML`/`outerHTML`/`insertAdjacentHTML`, `document.write`, `eval` or `new Function` in `client/src` outside tests (grep). Data-driven URLs are used only as `img.src`/`<img src>` (`BrandLogoOverlay.jsx:43`, `CeremonyBrandCard.jsx:48`, `bgImageCache.js:47`, …), where a `javascript:` URL does not execute. Every `a.href = url` is a locally created download URL (`PerfLogHUD.jsx:143`, `SystemSettings.jsx:33`, …). There are no CSS `url(${…})` sinks.
- `injectRuntimeConfig`: the origin is validated as http(s), has no credentials, query or path (`runtimeConfig.js:60-91`), and is emitted via `JSON.stringify(...).replace(/</g, '\\u003c')` (`:154`). This is safe.

**Headers (helmet 8 defaults, `app.js:36`)**: HSTS (`max-age=31536000; includeSubDomains`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: no-referrer`, COOP `same-origin`, `Origin-Agent-Cluster`, `X-DNS-Prefetch-Control: off`, `X-Permitted-Cross-Domain-Policies: none`, `X-XSS-Protection: 0`, and `X-Powered-By` removed. CSP is off and CORP is loosened (A5M-18). Caddy: automatic HTTPS and the http→https redirect. It adds nothing else (`a1v:Caddyfile.template:20-23`).

**Error answers**: every handled error answers a fixed sentence or a validator's own sentence. `asyncRoute` logs the stack server-side and answers only `internal error` (`asyncRoute.js:32-33`). The verify worker's error text is not sent to the client (`races.js:278` → asyncRoute). The API 404 reflects the URL in JSON only (`staticClient.js:171`). The gap is the unhandled path (A5M-08).

**Other**
- There are no redirects in the server (no open redirect), and no deep-merge of request JSON. Body spreads create own properties, so a JSON `"__proto__"` key cannot change a prototype.
- Regexes on user input other than A5M-02 and A5M-03 are linear or anchored: `guards.js:26-84` (measured 0.46 ms on a 16 000-character id), brand colours (`brands.js:121`), `isValidId`, `playerNames.mjs:31`, `raceShortKey.mjs:70`.
- `Date.parse` input is bounded: the result is checked for NaN, then for order, then for ≤366 days (`races.js:190-199`).
- Timing-safe comparison is used where a secret is compared (the bootstrap token).
- The container runs as the non-root `node` user (uid 1000), and only `/app/data` is owned by it (`server/Dockerfile:189`, `:188`). In production the app is not published, only Caddy's 80/443 (`a1v:docker-compose.prod.yml:51-53`, `:71-73`). ufw allows only 22, 80 and 443 (`a1v:install.sh:234-239`).
- Installer secrets: generated with `openssl rand` (`install.sh:79`). `racearena.env`, `install.conf` and `msmtprc` are written 600 through `install -m` (`:294`, `:175`, `:303`), and `/etc/racearena` is 700 (`:173`, `:276`). Passwords are read with `read -s`, never stored, and passed on stdin (`:130-139`, `:318`, `:325`; `ra-admin.mjs:15-16`, `:34-41`). `printf` is a bash builtin, so the SMTP password never appears in a process list. `install.conf` holds no passwords (`:174-175`).
- The backup restore refuses tar entries that escape the target (`backup.mjs:349-351`). The archive must be outside the data root (`:235-236`).
